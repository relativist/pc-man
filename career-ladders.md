# Карьерные лестницы игры "Компьютерщик"

## 1. Назначение документа

Документ фиксирует:

- старт карьеры героя;
- карьерные ветки;
- последовательности переходов между должностями;
- правила повышения;
- правила смены компании;
- примеры обычных и золотых вакансий.

Документ дополняет [game-requirements.md](/home/rest/intabia/pc-man/game-requirements.md).
Таблицы зарплат, компаний, вакансий и заказов вынесены в [career-and-content-tables.md](/home/rest/intabia/pc-man/career-and-content-tables.md).
Пул вакансий и заданий по веткам и уровням вынесен в [branch-vacancies-and-orders.md](/home/rest/intabia/pc-man/branch-vacancies-and-orders.md).

## 2. Общая логика карьеры

Старт героя:

- герой закончил университет;
- возраст: 21 год;
- стартовый статус: безработный;
- стартовая профессия в карьере: `Junior QA`.

Правила поиска работы:

- поиск первой работы занимает от 1 до 3 игровых дней;
- за один поиск герой получает от 1 до 3 вакансий;
- из найденных вакансий можно выбрать только 1;
- вакансии принадлежат разным компаниям;
- вакансии могут иметь шуточные названия;
- редкие вакансии могут иметь золотой статус.

Правила роста:

- герой повышает квалификацию через книги и выполнение заданий;
- когда квалификация достигает нужного порога, у героя появляется возможность попросить повышение;
- если текущая компания дает повышение, герой остается в ней и занимает новую должность;
- если текущая компания отказывает, герой может искать новую работу в другой компании;
- переход на новую должность происходит мгновенно;
- работу потерять нельзя.

## 3. Количество ступеней

Я предлагаю использовать `7` должностных ступеней для основных карьерных веток.

Это дает:

- более плавный рост;
- больше ощущения карьеры;
- удобные точки для перехода между ветками;
- нормальный баланс между длиной игры и сложностью контента.

Базовая схема ступеней:

1. `Junior`
2. `QA / Engineer / Specialist / PM`
3. `Middle`
4. `Strong Middle`
5. `Senior`
6. `Lead`
7. `Head / Principal`

## 4. Главная стартовая ветка

Стартовая карьерная цепочка:

```text
Безработный выпускник
-> Junior QA
-> QA
-> Middle QA
-> Strong Middle QA
-> Senior QA
-> Lead QA
-> Head of QA
```

Это главная отправная точка всей карьеры.

### 4.1. Формальный старт карьеры

Для MVP старт героя нужно зафиксировать без альтернативных начальных IT-ролей:

```text
Безработный выпускник
-> Поиск первой работы (1-3 дня)
-> 1-3 вакансии
-> выбор 1 вакансии
-> Junior QA
```

Правила стартового входа:

- герой начинает без работы;
- первая карьерная развилка не уводит в разные профессии, а только в разные компании с вакансией `Junior QA`;
- поиск первой работы всегда занимает от `1` до `3` игровых дней;
- за один цикл поиска герой получает от `1` до `3` вакансий;
- после выбора вакансии герой мгновенно становится `Junior QA`;
- старт через `Junior IT` или другую общую техроль для MVP не используется.

### 4.2. Почему старт именно через QA

Такой старт нужен для структуры всей игры:

- QA дает самый понятный и дешевый вход в первую работу;
- через QA игрок рано знакомится с квалификацией, повышениями и сменой компании;
- QA-ветка служит общей базой для дальнейших переходов в инженерные, управленческие и смежные роли.

## 5. Правила переходов между ветками

Основные принципы:

- ранний карьерный рост идет внутри QA-ветки;
- первые боковые переходы можно открывать после `Middle QA`;
- полноценная смена специализации открывается после `Senior QA`;
- при смене ветки герой всегда начинает новую ветку с `Junior`-позиции;
- рост внутри новой ветки снова идет последовательно.

Ключевое правило:

```text
Senior QA -> Junior новой ветки
```

Например:

- `Senior QA` -> `Junior Backend Engineer`
- `Senior QA` -> `Junior Frontend Engineer`
- `Senior QA` -> `Junior PM`
- `Senior QA` -> `Junior Pentester`

### 5.1. Канонические точки развилки

Чтобы переходы были прозрачными, для MVP полезно закрепить такие точки:

| Текущая роль | Что открывается | Тип перехода |
|---|---|---|
| `Безработный выпускник` | `Junior QA` | первая работа |
| `Middle QA` | `Junior Analyst` | ранняя смежная развилка |
| `Senior QA` | `Junior Backend Engineer`, `Junior Frontend Engineer`, `Junior PM`, `Junior Pentester`, `Junior Analyst` | полная смена ветки |
| `Lead QA` | `Junior PM`, `Engineering Manager` | поздний управленческий переход |
| `Lead Backend Engineer` | `Junior PM`, `Engineering Manager` | технический переход вверх |
| `Lead Frontend Engineer` | `Junior PM`, `Engineering Manager` | технический переход вверх |
| `Lead PM` | `Engineering Manager` | переход в позднюю CTO-ветку |

### 5.2. Общие правила смены ветки

- переход между ветками не переносит героя сразу на `Middle` или `Senior` в новой профессии;
- прошлые роли и квалификации влияют на доступность перехода, но не заменяют полноценный прогресс внутри новой ветки;
- зарплата после смены ветки определяется новой должностью и новой компанией, а не старым местом работы;
- переход в новую ветку должен ощущаться как осознанный откат по должности ради долгосрочного роста.

## 6. Основные карьерные ветки

### 6.1. QA-ветка

```text
Junior QA
-> QA
-> Middle QA
-> Strong Middle QA
-> Senior QA
-> Lead QA
-> Head of QA
```

Точки перехода:

- после `Middle QA` можно открыть ветку `Analyst`;
- после `Senior QA` можно перейти в:
  - `Backend`
  - `Frontend`
  - `PM`
  - `Pentester`
- после `Lead QA` можно двигаться в управленческие роли.

Формальные правила QA-ветки:

- это единственная обязательная стартовая ветка MVP;
- до `Middle QA` герой растет только внутри QA-лестницы;
- `Middle QA` открывает первую "мягкую" развилку в `Analyst`;
- `Senior QA` открывает главную смену специализации в соседние ветки;
- `Lead QA` и `Head of QA` позволяют остаться в чисто QA-карьере без обязательной смены профессии.

### 6.2. Backend-ветка

```text
Junior Backend Engineer
-> Backend Engineer
-> Middle Backend Engineer
-> Strong Middle Backend Engineer
-> Senior Backend Engineer
-> Lead Backend Engineer
-> Principal Backend Engineer
```

Типичный вход:

- через `Senior QA`
- позже через другие технические ветки

Дальнейшие переходы:

- в `PM`
- в `CTO`-ветку

Формальные правила Backend-ветки:

- базовый вход в MVP идет из `Senior QA`;
- при входе из QA герой начинает с `Junior Backend Engineer`;
- дальнейший рост идет строго по 7-ступенчатой лестнице без пропуска ступеней;
- поздняя цель ветки внутри техкарьеры: `Principal Backend Engineer`;
- после сильных ролей `Senior` / `Lead` возможен переход в `PM` или позднюю `CTO`-ветку.

### 6.3. Frontend-ветка

```text
Junior Frontend Engineer
-> Frontend Engineer
-> Middle Frontend Engineer
-> Strong Middle Frontend Engineer
-> Senior Frontend Engineer
-> Lead Frontend Engineer
-> Principal Frontend Engineer
```

Типичный вход:

- через `Senior QA`

Дальнейшие переходы:

- в `PM`
- в `CTO`-ветку

Формальные правила Frontend-ветки:

- базовый вход в MVP идет из `Senior QA`;
- при входе из QA герой начинает с `Junior Frontend Engineer`;
- ветка повторяет общую 7-ступенчатую инженерную схему;
- поздняя цель ветки внутри профессии: `Principal Frontend Engineer`;
- после сильных ролей `Senior` / `Lead` возможен переход в `PM` или позднюю `CTO`-ветку.

### 6.4. PM-ветка

```text
Junior PM
-> PM
-> Middle PM
-> Strong Middle PM
-> Senior PM
-> Lead PM
-> Head of Delivery
```

Типичный вход:

- через `Senior QA`
- через сильные технические ветки

Формальные правила PM-ветки:

- вход возможен из `Senior QA` или из сильной техветки;
- при смене профессии герой начинает с `Junior PM`;
- PM-ветка считается полноценной основной веткой с `7` ступенями;
- ее поздняя вершина в MVP: `Head of Delivery`;
- из `Lead PM` можно открыть поздний переход в `Engineering Manager` и дальше в `CTO`-ветку.

### 6.5. Pentester-ветка

```text
Junior Pentester
-> Pentester
-> Middle Pentester
-> Strong Middle Pentester
-> Senior Pentester
-> Lead Pentester
-> Head of Security Testing
```

Типичный вход:

- через `Senior QA`
- через backend-ветку позже

### 6.6. Analyst-ветка

```text
Junior Analyst
-> Analyst
-> Middle Analyst
-> Strong Middle Analyst
-> Senior Analyst
-> Lead Analyst
-> Head of Analytics
```

Типичный вход:

- через `Middle QA`
- через `Senior QA`

## 7. CTO-ветка как поздняя карьера

`CTO` лучше не делать обычной веткой с самого низа. Это поздняя карьерная цель.

Предлагаемая цепочка:

```text
Lead Backend Engineer / Lead Frontend Engineer / Lead PM
-> Engineering Manager
-> Architect
-> Technical Director
-> Acting CTO
-> CTO
```

Особенности:

- это endgame-ветка;
- сюда лучше попадать из сильной технической или управленческой карьеры;
- для входа могут требоваться несколько развитых квалификаций одновременно.

Формальные правила поздней CTO-ветки:

- `CTO` не является стартовой и не является обычной базовой веткой;
- точка входа в позднюю цепочку начинается с `Engineering Manager`;
- прямой вход в `Engineering Manager` доступен только после сильной технической или управленческой роли;
- `Architect`, `Technical Director`, `Acting CTO`, `CTO` являются уже не "сменой профессии", а endgame-ростом;
- для поздней CTO-ветки допустимо требовать несколько развитых специализаций одновременно.

## 8.1. Каноническое дерево переходов MVP

Ниже полезно зафиксировать главную карту переходов в одном месте:

```text

   -> Junior Analyst
-> Strong Middle QA

   -> Junior Frontend Engineer

Junior Backend Engineer

-> Middle Backend Engineer

-> Frontend Engineer
```

## 8. Как работает повышение

Механика повышения:

1. Герой читает книги.
2. Герой выполняет задания и разовые заказы.
3. Растет квалификация по нужной специальности.
4. При достижении порога появляется предложение: можно попросить повышение.
5. Компания либо дает повышение, либо не дает.
6. Если компания отказала, герой ищет новую работу.

Это создает две линии роста:

- рост внутри текущей компании;
- рост через смену компании.

## 9. Роль компании в карьере

Компания влияет на:

- размер зарплаты;
- доступность повышения;
- тип вакансий;
- шуточное оформление.

Зарплата:

- базовая зарплата задается должностью;
- конкретная компания модифицирует ее примерно на `10-15%`;
- золотая вакансия может дать еще более выгодные условия.

## 10. Золотые вакансии

Правила:

- шанс золотой вакансии: `5%`;
- золотая вакансия дает больше денег;
- других особых эффектов у золотой вакансии пока нет.

## 11. Примеры шуточных вакансий

### 11.1. Junior QA

- `Junior QA по подсчету блох на обезьянах в зоопарке лысых рыб`
- `Младший тестировщик кнопки "Ой" в НИИ Неловких Интерфейсов`
- `Junior QA по проверке носков для умных холодильников`

### 11.2. Backend

- `Junior Backend Engineer по спасению API чайников`
- `Бэкендер учета котиков в АО "Мяу и Схема"`
- `Серверный стажер по маршрутизации пельменей`

### 11.3. Frontend

- `Junior Frontend Engineer по выравниванию кнопок в браузере бабушки`
- `Верстальщик всплывающих окон в ООО "Пиксель и Слезы"`
- `Frontend-инженер по борьбе с CSS в Центре Народного Флекса`

### 11.4. PM

- `Junior PM в департаменте вечного созвона`
- `Координатор дедлайнов, которых никто не видел`
- `PM по контролю хаоса в компании "Сроки Потом"`

### 11.5. Pentester

- `Junior Pentester по взлому домофонов цифрового царства`
- `Стажер аудита дыр в ООО "Безопасненько"`

## 12. Примеры золотых вакансий

- `Золотая вакансия: Junior QA в Королевском Институте Нахождения Багов`
- `Золотая вакансия: Junior Backend Engineer в Фонде Великого API`
- `Золотая вакансия: Junior PM в Империи Согласованных Таблиц`

## 13. Рекомендуемая итоговая структура MVP

Для MVP я бы оставил такие основные ветки:

1. `QA`
2. `Backend`
3. `Frontend`
4. `PM`
5. `Pentester`
6. `Analyst`
7. поздняя `CTO`-ветка

Главный маршрут игрока:

```text
Безработный
-> Junior QA
-> QA
-> Middle QA
-> Strong Middle QA
-> Senior QA
-> Junior Backend / Junior Frontend / Junior PM / Junior Pentester
-> дальнейший рост
```
